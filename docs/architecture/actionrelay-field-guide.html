One request can become an action

ActionRelay combines automatic routine fulfillment with traceable human handling.

What ActionRelay does

A complete approved routine request can receive its answer in the ticket. Exceptions reach a reviewer with evidence and uncertainty preserved.

Two paths, one workflow

Low band is a candidate signal. A versioned procedure, verified evidence and live application permission determine automatic authority.

Current delivery state

The HTML presentation uses isolated synthetic memory. The backend write gate and newer Auditor/feedback permissions require implementation and acceptance.

What remains known

Python 3.13, FastAPI, Pydantic and SQLite are the recorded local stack. The HTML/CSS/JavaScript demo makes no model calls.

What remains unknown

CDIT operational data, product guidance, actual workload, SLAs and measured productivity. A future CDIT-data version needs authorized sources and integration.

Manny owns Coordinator, Triage, Escalation and SQL. Shawn owns Knowledge, Troubleshooting and Documentation. User, Staff, Auditor-capable Staff and Admin are the four demo accounts.

User needs define acceptance

Each requirement below identifies the user task and the evidence needed.

UN-01Staff

Understand the assigned case

As Staff, I need an evidence-linked summary and classification because I must decide how to handle exceptions.

Acceptance evidence Category, band and rationale agree with supplied case/policy evidence.

UN-02Staff

Verify the guidance

As Staff, I need approved source IDs, sections and versions because product instructions must be checkable.

Acceptance evidence No fabricated citations or unsupported material claims.

UN-03Staff

Recognize stop conditions

As Staff, I need bounded steps and explicit escalation triggers because some cases require human judgment.

Acceptance evidence All defined must-escalate synthetic cases take the human route.

UN-04Staff

Review factual drafts

As Staff, I need a complete cited note because review should preserve facts and uncertainty.

Acceptance evidence Required fields, source support and unknowns are validated.

UN-05Human reviewer

Receive a useful handoff

As a reviewer, I need facts, evidence gaps, attempted checks and the requested decision because I must pick up work without inventing context.

Acceptance evidence A versioned packet carries the basis, stop reason and next decision.

UN-06Admin

Control access and assignments

As Admin, I need attributable account and assignment controls because read and write privileges differ.

Acceptance evidence Non-Admin management writes are denied and changes are audited.

UN-07User

Get an approved routine answer

As User, I need a verified public resource inside my ticket because an eligible request can be fulfilled without waiting for Staff.

Acceptance evidence Approved complete request receives one reply and Resolved transition atomically.

UN-08Product Health

Inspect operational metadata

As an authorized operator, I need bounded run/error/version metadata because I must investigate behavior without exposing ticket content.

Acceptance evidence Allowlisted fields, retention and content exclusion pass synthetic checks.

UN-09Auditor

Classify assigned work

As Auditor, I need all-ticket read visibility and assigned-only classification because seeing the queue must not grant extra writes.

Acceptance evidence Ordinary Staff scope and Auditor read/write scope are tested separately.

UN-10Auditor

Revise with reasons

As Auditor, I need the current decision visible and earlier versions preserved because new evidence can change a classification.

Acceptance evidence Reason, actor, timestamp, expected previous version and immutable history are recorded.

UN-11Admin / Auditor

Review optional feedback

As Admin, I need version-specific notes and flags because oversight must identify the exact decision. As Auditor, I can retain that decision.

Acceptance evidence Feedback reaches the author and never silently changes a classification or starts a run.

Run the complete case and keep the return path

The normal path and human/recovery loops use the same correlated case and version identifiers.

Public form request

The exact complete request matches a curated public-resource procedure. Retrieve the approved IDNYC materials link, verify it and all gate checks, then commit the local reply and Resolved transition together. The requester sees the source and answer.

Personal W-2

A request for a personal record remains open. A blank form or public advice does not fulfill it. Prepare supported general guidance and the requested human decision. No payroll record access or tax advice is implied.

Unknown or mixed case

Preserve item/source spans, unknown category or band and any potential-urgent concern. A blocked item prevents whole-case automatic resolution. Independent supported guidance does not mean the entire case is complete.

Withholding correction

An Auditor initially records Payroll/Medium. New synthetic evidence about unchanged settings and a different calculation supports a reasoned Technical Issues revision. The initial decision stays in history.

Feedback loop

Admin notes or flags version 2. The author receives the exact note/version in Feedback and may keep the decision. A separate human correction submitted for processing creates a new case/run version.

The application enforces the write

Agents return the supported candidate. A deterministic application capability executes the bounded local operation.

Allowed routine operation

An exact complete Low-band request for a curated public blank form or resource may receive one in-ticket answer and Resolved transition without per-case human approval.

Live gate

Recheck identity/capability, case and source/policy versions, full procedure match, all-item completion, verified claims and absence of stop triggers.

One transaction

Reply, Resolved status, incremented case version and audit/operation record commit together. A unique operation key and expected version reject duplicates or competing stale candidates.

Commit uncertainty

Query the original operation key. Return an existing commit. Revalidate before a definitively absent retry. An inconclusive ledger lookup stays unresolved and goes to recovery.

Excluded operations

No automatic closure, external email/phone/SMS, government submission, personal W-2 retrieval, account management, arbitrary SQL or self-granted permission.

Shared login

User has no internal-role navigation. A separate showcase exposes isolated role previews. Every application route still needs server-side authorization.

Unknown stays open

A valid category and band are required before resolution or closure. High urgency does not grant authority. Auditor feedback cannot change a lifecycle state.

Data and trust

Untrusted tickets, sources and model text cannot change policy or tool scope. Approved public links do not authorize private-record access or CDIT product claims.

Retention and Product Health

Detailed synthetic run/error metadata retains for 30 days, account/access audit for 90 days, and aggregate summaries up to 12 months. The explicit reset/purge and accelerated-clock checks remain required.

Current decision, earlier versions and optional feedback

Each case retains its exact decision versions and their authors.

Current above history

Show the latest category, band, reason, author and timestamp outside history. Every earlier version keeps its original values.

Revise deliberately

An assigned Auditor may revise their own latest decision with a new reason and expected previous version. Closed cases are read-only and Admin overrides cannot be superseded by an Auditor.

Admin oversight

Admin sees all cases with the current decision highlighted, prior versions expandable, and optional note/flag controls bound to one decision version.

Optional feedback

The recipient sees the note/flag for the exact version. No acknowledgment or revision is mandatory. Clearing a flag preserves the earlier event and notes.

Concurrency

A save includes the expected previous version. If another decision was recorded first, reject stale overwrite and refresh the history.

Correction is a separate action

A new submitted correction creates a new linked run and invalidates affected stages. Feedback alone never reruns agents, promotes a rule or changes status.

Explore activity without confusing it with a snapshot

The synthetic timeline and yearly wheels measure different things.

Status at cutoff

Each ticket in scope has one status at the cutoff. The wheel includes carryover from earlier years. Open backlog adds the open statuses.

Matched-period activity

Count received, resolved and closed actions during the same calendar dates in each year. A ticket can count in more than one activity row. These rows do not sum to total tickets.

Shared colors and exact counts

Both wheels use one color mapping for each status. Show ticket counts, shares, count changes and relative changes. A zero prior denominator has no relative baseline.

Date selection

Day/month/year filters and date ranges narrow activity. Scroll weekly or monthly, pin exact values, and use the interval up to the next marker to inspect the earlier date. Year view fits up to ten years.

Open items, ownership and sources

Approved product intent must still be connected to implemented and tested contracts.

Backend routine write integration

Implement and test the procedure registry, operation capability, transactional commit and duplicate/concurrent/uncertain-commit behavior.

Permission implementation

Add server-side all-ticket Auditor reads while retaining assigned-only classifications, read-only account directory and Admin-only management.

Feedback persistence

Implement exact recipient/version binding, immutable feedback/flag history and independent correction submission.

Contracts and schema

Approve concrete stage/procedure/schema versions, lifecycle/operation storage, optimistic concurrency and recovery semantics.

Retry and evidence thresholds

Choose finite attempts, delays/timeouts and permitted transient failures. Calibrate evidence/claim thresholds on a labeled holdout.
