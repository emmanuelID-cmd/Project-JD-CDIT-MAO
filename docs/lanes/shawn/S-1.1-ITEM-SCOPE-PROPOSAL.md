## 2. F-3: say what the attention check did

### Problem

When no fixture patterns are configured, `attention_signal` is `None` (`runtime.py:127-128`). The handoff then carries `parent_attention_flagged = False` and no `attention_ref`. This reads the same as "the check ran and nothing matched". Every connected item has Unknown urgency, where Q-B says the flag applies.

### Proposed field

`attention_check: Literal["potential_attention", "no_configured_match", "check_not_run"] | None = None`

| Value | Meaning | Rules |
| :--- | :--- | :--- |
| `potential_attention` | A configured phrase matched inside this item's span. | `attention_ref` must be set. This already implies `parent_attention_flagged = True`. |
| `no_configured_match` | The literal check ran on this item's span and no configured phrase matched. This is not a risk assessment (`attention.py:3-4`). | `attention_ref` must be `None`. The parent flag may be true if another item matched. |
| `check_not_run` | The literal check did not run, for example because no patterns were configured. | `attention_ref` must be `None` and `parent_attention_flagged` must be `False`. |
| `None` (default) | Triage did not say. Kept so current handoffs stay valid. | The existing S-1 rules only. |

New rejection reasons: `attention_check_ref_mismatch` and `attention_check_not_run_but_parent_flagged`.

**Names.** The review suggested `flagged`, `none_found`, and `not_assessed`. They are renamed for two reasons:

- `AttentionSignal.status` already uses `not_assessed` for "the check ran and nothing matched". Reusing it for "did not run" would mean the opposite in the item scope.
- `none_found` sounds like "no risk found", which `attention.py` explicitly rules out.

`potential_attention` reuses Manny's own term.

### Who reads it

- **Knowledge:** does not read it. Attention fields never filter or rank retrieval (S-1 rule, unchanged).
- **Troubleshooting:** does not read it.
- **Documentation:** adds one `unknown` line when the item has no attention reference.

| `attention_check` | Documentation line (proposed) |
| :--- | :--- |
| `potential_attention` | Unchanged: "Attention flag present on this item; see the Triage attention record. Only a human may clear it." |
| `no_configured_match` | "Attention check: no configured phrase matched this item. This is not a risk assessment." |
| `check_not_run` | "Attention check: did not run for this item. Staff judge urgency without it." |
| `None` | "Attention check: Triage did not say whether it ran for this item." |

The existing line for another item's flag still appears when `parent_attention_flagged` is true.

## 3. F-4: cite the taxonomy, not the policy version

### Problem

Triage binds each category to two sources (`runtime.py:260-283`): the item's case message, and the taxonomy reference `SYN-TICKET-CATEGORY-TAXONOMY vsha256-<16 hex>`, with locator `category_sha256:<64 hex>`. The S-1 rule at `contracts/handoffs.py:215-216` requires every `policy_rule` source to carry the run's policy version. The connector therefore drops the real taxonomy reference and builds a stand-in, `<policy_version> v<policy_version> #category-taxonomy-sha256:<hash>` (`knowledge_connector.py:127-139`). The hash survives, but the cited source is wrong. A placeholder `"unavailable"` is also used if the taxonomy is missing, although that case cannot happen (F-9).

### Proposed rule

Mirror the rule Triage already applies to its own items (`multi_item.py:129-137`) in the shared contract:

```python
CATEGORY_TAXONOMY_SOURCE_ID = "SYN-TICKET-CATEGORY-TAXONOMY"
_TAXONOMY_LOCATOR = re.compile(r"category_sha256:([0-9a-f]{64})")

def is_category_taxonomy_ref(source: SourceRef) -> bool:
    if source.kind is not SourceKind.POLICY_RULE or source.source_id != CATEGORY_TAXONOMY_SOURCE_ID:
        return False
    match = _TAXONOMY_LOCATOR.fullmatch(source.locator or "")
    return match is not None and source.version == f"sha256-{match.group(1)[:16]}"
```

In `TriageHandoff._item_scope_consistent`, for each category source:

- a `policy_rule` source with the taxonomy source ID must pass `is_category_taxonomy_ref`, otherwise `item_claim_taxonomy_source_mismatch`;
- any other `policy_rule` source must still carry the run's policy version (`item_claim_policy_version_mismatch`, unchanged).

**Why this design:**

- **Narrow.** Only the one taxonomy source ID is exempt from the policy-version check. A generic exemption for any hash-like locator would let any policy rule escape it.
- **Self-consistent.** The version must be derived from the full digest, so a mismatched pair is rejected.
- **No new source kind.** A new `SourceKind` would touch every `SourceRef` user and Manny's taxonomy validator (`development_examples.py:87`).
- **Same rule on both sides.** Triage and the contract then accept the same references.

**Limit.** The receiver checks shape only. Whether the taxonomy is the trusted one is still decided by Triage's pinned loader (`runtime.py:167`).

## 4. Prototype evidence (scratch only)

The proposal was applied in a detached scratch worktree at `a363724`, checked out with LF endings. The worktree has been removed, and nothing from it was committed.

| Step | Result |
| :--- | :--- |
| Baseline | 618 passed |
| Shawn side only: contract plus the Documentation line | 618 passed. Manny's current connector output still validates, so the change is backward compatible. |
| Plus Manny's side: the connector change below | 618 passed |
| 25 receiver probes with the real Coordinator, Triage runtime, a fake model client, and Shawn's agents | 25 passed, 0 failed |

**What the probes showed:**

- **Attention status.**
  - No patterns configured: both items report `check_not_run` with no parent flag.
  - A literal only in item 2: item 1 reports `no_configured_match` and item 2 reports `potential_attention` with its reference. Both carry the parent flag.
- **Taxonomy citation.** The category cites `SYN-CASE-06 v1 #message` and `SYN-TICKET-CATEGORY-TAXONOMY vsha256-02b212725e66b9aa`. These match Triage's taxonomy version and digest, and the policy stand-in is gone. The claim cites the same sources.
- **Rejections.** Each of these is rejected with its reason:
  - `potential_attention` without a reference;
  - a reference with `no_configured_match`;
  - `check_not_run` with a parent flag;
  - an unknown value;
  - a taxonomy version not derived from the digest;
  - a locator without the full digest;
  - an upper-case digest;
  - another policy source on the wrong version.

  A legacy handoff (`attention_check` missing, policy stand-in) is still accepted.
- **End to end.** After an Auditor band, Knowledge, Troubleshooting, and Documentation ran for each of the three values. Each draft has the expected attention line and no privacy finding. Its category line cites the taxonomy source.

**Note on rendering.** The plain-text draft shows an inference's basis, not its sources. The taxonomy citation is therefore in the structured draft lines, not in the rendered text. This is existing behaviour, and no change is proposed.

**Connector change used in the prototype.** This is for feasibility only. Manny owns this file and may implement it differently.
